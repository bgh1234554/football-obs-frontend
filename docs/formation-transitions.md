# 포메이션 변경 시 선수 배치 유지

포메이션 선택을 바꾸면 **현재 편집 중인 슬롯**을 기준으로 선수를 옮긴다. API의 `grid`는 같은 포메이션 안에서만 의미가 있으므로, 서로 다른 포메이션 사이에서 `2:1`, `3:2` 등의 문자열을 직접 매칭하지 않는다. 직접 드래그한 배치, 교체 선수의 원본 저장 키, 빈 슬롯과 풀폼 입력값도 함께 유지한다.

## 우선 대응하는 포메이션 관계

다음은 앱이 지원하는 포메이션을 대상으로 한 **배치 전환 규칙**이다. 같은 묶음이라고 전술·압박 방식까지 동일하다는 뜻은 아니다. 자료의 역할 설명을 바탕으로, 각 팀의 별도 지시가 없는 경우 사용할 일대일 대응을 정했다. 같은 묶음 내의 어느 두 포메이션을 선택해도 좌우와 대응 선수가 보존된다.

| 묶음 | 포메이션 | 유지할 선수와 이동 방식 |
| --- | --- | --- |
| 다이아몬드·중앙 공격형 미드필더와 투톱 | `4-3-1-2`, `4-1-2-1-2`, `4-1-3-2` | 백4·투톱·CAM 유지. 중앙의 홀딩 역할은 CDM, 좌우 중원은 같은 쪽 중원으로 이동. `4-1-3-2`의 넓은 두 자리는 좌우 중원과 대응. |
| 백3·중원3·투톱 | `3-5-2`, `3-1-4-2`, `5-3-2` | 센터백3·중원3·투톱 유지. 양쪽 윙백만 같은 측면에서 높이를 변경. |
| 백3·중원2·전방3 | `3-4-3`, `3-4-2-1`, `5-2-3`, `5-4-1` | 센터백3·윙백2·중원2·중앙 공격수 유지. 전방 양옆은 같은 쪽 윙어/공격형 미드필더/측면 미드필더로 대응. |
| 백4·중앙 중원3·원톱 | `4-3-3`, `4-1-2-3`, `4-1-4-1`, `4-5-1`, `4-3-2-1` | 백4·홀딩 역할·좌우 중앙 중원·원톱 유지. 전방 양옆의 폭과 높이만 변경. |
| 백4·더블 피벗·CAM·원톱 | `4-2-3-1`, `4-2-1-3`, `4-4-1-1` | 백4·중앙 중원2·CAM·원톱 유지. 양쪽 윙어/측면 미드필더만 이동. |
| 백4·중원2·투톱 | `4-4-2`, `4-2-2-2` | 백4·중앙 중원2·투톱 유지. 양쪽 측면 미드필더는 같은 쪽 공격형 미드필더로 이동. |

특히 `3-5-2 → 5-3-2`에서 기존 오른쪽 센터백을 새 오른쪽 윙백으로 옮기지 않는다. `3-4-3 → 3-4-2-1`에서는 중앙 공격수를 원톱으로 남기고, 오른쪽/왼쪽 윙어를 오른쪽/왼쪽 공격형 미드필더로 옮긴다.

## 조사 근거와 앱의 해석

- [Coaches’ Voice: 4-4-2 diamond](https://learning.coachesvoice.com/cv/4-4-2-diamond-football-tactics-explained-klopp-potter-allegri/)는 단일 피벗, 좌우 8번, 10번, 투톱 구조를 설명한다. `4-3-1-2`와 `4-1-2-1-2`의 대응에 사용했다. `4-1-3-2`까지의 연결은 앱의 기존 좌표·역할에 맞춘 배치 정책이다.
- [Coaches’ Voice: 3-5-2](https://learning.coachesvoice.com/cv/3-5-2-formation-conte-mourinho-guardiola/)는 센터백3, 윙백2, 중원3, 투톱과 윙백이 내려와 백5가 되는 구조를 설명한다. `3-1-4-2`의 단일 피벗은 앱의 `3-5-2` 중앙 홀딩 슬롯과 대응시켰다.
- [Coaches’ Voice: 3-4-3](https://learning.coachesvoice.com/cv/3-4-3-formation-football-tactics-explained-tuchel-conte-pochettino-southgate/)는 좁은 전방3을 `3-4-2-1`로 부르기도 하며, 수비 시 `5-2-3`/`5-4-1`로 바뀌는 관계를 설명한다.
- [Coaches’ Voice: 4-1-4-1](https://learning.coachesvoice.com/cv/4-1-4-1-formation-football-tactics-explained/)는 `4-3-3`과 단일 피벗을 공유하며 윙어가 내려오는 관계를 설명한다. `4-1-2-3`/`4-5-1`은 이 역할 구성을 앱 좌표에 대응시킨 것이고, `4-3-2-1`의 전방 두 명은 [해당 포메이션 설명](https://learning.coachesvoice.com/cv/4-3-2-1-formation-football-tactics/)에 따라 안쪽의 공격형 미드필더로 대응한다.
- [Coaches’ Voice: 4-2-3-1](https://learning.coachesvoice.com/cv/4-2-3-1-formation-fundamentals/)의 더블 피벗·10번·측면 공격수·원톱 구성을 기준으로, 앱의 `4-2-1-3`과 `4-4-1-1`을 대응시켰다. 이 세 표기를 동의어로 단정한 것이 아니라 같은 선수들을 유지하기 위한 해석이다.
- [Coaches’ Voice: 4-2-2-2](https://learning.coachesvoice.com/cv/4-2-2-2-football-tactics-explained-rangnick-hasenhuttl-pellegrini/)의 백4·더블 피벗·전진한 중원2·투톱 구성을 기준으로 `4-4-2`의 측면 중원을 안쪽으로 옮기도록 정했다.

## 추가로 조사·검증한 전환 관계

아래는 위의 여섯 묶음 사이를 연결하거나, 역할 하나가 달라지는 전환이다. 원톱+CAM과 투톱 사이의 대응은 명시적으로 고정한다. 확인된 한 단계 이동은 양방향으로 연결하고 **최대 네 단계까지 합성**한다. 확인된 연결 경로를 일반 위치 최적 배정보다 우선하며, 연결 경로가 없을 때만 일반 최적 배정을 사용한다. 구체적으로 누가 전진/후퇴할지는 현재 슬롯을 기준으로 정하며, 팀의 실제 전술 지시를 추측해 고정하지 않는다.

| 확인된 한 단계 이동 | 선수 흐름 |
| --- | --- |
| `4-3-3 ↔ 4-1-4-1` | 양쪽 윙어 ↔ 같은 쪽 측면 미드필더. 홀딩과 중앙 중원, 원톱은 유지. |
| `4-3-3 ↔ 3-4-3` | 홀딩 미드필더 ↔ 백3 중앙 센터백. 양쪽 풀백 ↔ 같은 쪽 윙백. 전방 3명과 양쪽 중앙 중원은 유지. |
| `4-1-2-3 ↔ 3-4-3` | 홀딩 미드필더 ↔ 백3 중앙 센터백. 양쪽 풀백 ↔ 윙백. 전방 3명 유지. |
| `3-4-3 ↔ 5-2-3` | 양쪽 윙백만 내려가/올라가며 백3·중원2·전방3 유지. |
| `4-2-1-3 ↔ 3-3-1-3` | 피벗 한 명이 중앙 센터백으로 내려가고 풀백2는 양쪽 측면으로 이동. CAM·전방3 유지. |
| `3-4-3 ↔ 3-3-1-3` | 백3·측면2·전방3 유지. 중앙 중원 두 명 중 한 명은 홀딩, 다른 한 명은 CAM으로 이동. |
| `3-5-2 ↔ 3-4-1-2` | 백3·윙백2·투톱 유지. 중앙 중원 세 명에서 한 명이 CAM으로 전진. |
| `3-5-2 ↔ 3-5-1-1` | 백3·윙백2·중원3 유지. 투톱 중 한 명이 CAM 높이로 내려감. |
| `3-4-1-2 ↔ 3-4-2-1` | 백3·윙백2·중원2 유지. 투톱 한 명이 측면 공격형 미드필더로 이동. |
| `4-3-3 ↔ 4-2-3-1` | 백4·양쪽 윙어·원톱 유지. 중앙 중원 한 명이 CAM으로 전진해 더블 피벗 형성. |
| `4-3-1-2 ↔ 3-4-1-2` | DM이 센터백 둘 사이로 내려가고 풀백 둘이 윙백으로 올라감. 양쪽 CM·CAM·투톱 유지. |
| `4-3-2-1 ↔ 3-4-2-1` | DM이 센터백 둘 사이로 내려가고 풀백 둘이 윙백으로 올라감. 양쪽 CM·공격형 미드필더 둘·원톱 유지. |
| `4-5-1 ↔ 4-4-1-1` | DM이 CM으로 올라오고 기존 CM 한 명이 CAM으로 전진. 백4·양쪽 측면 미드필더·원톱 유지. |
| `4-2-3-1 ↔ 3-5-2` | 풀백2는 윙백, 양쪽 윙어는 같은 쪽 CM, 피벗 한 명은 백3 중앙, 다른 한 명은 홀딩에 남음. CAM은 기존 ST 옆으로 올라감. |
| `4-3-3 ↔ 4-3-1-2` | 원톱이 CAM으로 내려가고 양쪽 윙어가 같은 쪽 투톱으로 좁혀 들어옴. 백4·중원3은 유지. |

`4-3-3 → 5-2-3`을 직접 선택해도 `4-3-3 → 3-4-3 → 5-2-3`과 **동일한 선수 배치**가 된다. 원래 홀딩 선수는 백3 중앙에 남고, 원래 풀백 둘은 백5 양끝에 위치한다. `3-4-1-2 → 5-3-2`도 `3-5-2`를 거쳐 같은 방식으로 계산한다. 경로가 여러 개면 거치는 단계가 적은 것을 우선하고, 같은 단계 수에서는 선수 이동 비용이 낮은 경로를 선택한다.

23개 포메이션의 서로 다른 253개 조합 중 201개는 세 단계 이내, 나머지 52개는 네 단계의 확인된 이동을 거쳐 연결된다. 예를 들어 `4-4-2 → 5-4-1`은 네 단계 경로로 처리한다. 네 단계 전체가 특정 팀의 단일 전술 변화로 검증되었다는 뜻은 아니며, 각각 조사·검증한 한 단계 이동의 선수 대응을 합성한 결과다.

| 전환 | 보존할 구조와 앱의 대응 기준 |
| --- | --- |
| `4-3-3` / `4-1-2-3` ↔ `3-4-3` | 기존 센터백2와 전방3 유지. 홀딩 선수가 센터백 사이로 내려가고 풀백2는 같은 측면 윙백으로 이동. |
| `4-2-1-3` ↔ `3-3-1-3` | 센터백2·CAM·전방3 유지. 피벗 한 명이 센터백, 다른 한 명은 홀딩, 풀백은 측면으로 이동. |
| `3-4-3` ↔ `3-3-1-3` | 센터백3·양쪽 측면·전방3 유지. 중앙 중원2를 홀딩과 CAM으로 분리. |
| `3-5-2` ↔ `3-4-1-2` | 센터백3·윙백2·투톱 유지. 중앙 중원3 안에서 중원2+CAM으로 전환. |
| `3-4-1-2` ↔ `3-4-2-1` | 센터백3·윙백2·중원2 유지. CAM+투톱을 공격형 미드필더2+원톱으로 전환. |
| `4-4-2` ↔ `4-4-1-1` | 백4·중원4 유지. 투톱 중 한 명만 지원 공격수/CAM 높이로 이동. |
| `3-5-2` ↔ `3-5-1-1` | 센터백3·윙백2·중원3 유지. 투톱 중 한 명만 CAM으로 이동. |
| `4-3-3` ↔ `4-2-3-1` | 백4·전방 양옆·원톱 유지. 중앙 중원3 안에서 더블 피벗+CAM으로 전환. |
| `4-2-3-1` / `4-2-1-3` / `4-4-1-1` ↔ `4-4-2` / `4-2-2-2` | 백4·중앙 중원2·좌우 측면 유지. 기존 ST는 왼쪽 ST, CAM은 오른쪽 ST로 이동하며 역방향에서는 그 선수가 CAM으로 복귀. `4-2-2-2`의 두 공격형 미드필더에는 양쪽 윙/측면 미드필더가 같은 쪽으로 이동. |
| `4-2-3-1` ↔ `4-3-2-1` | 백4·원톱 유지. 양쪽 공격수는 같은 쪽 좁은 공격형 미드필더, 중앙의 CAM은 중원에 합류. |
| `4-1-4-1` ↔ `4-4-2` | 백4·측면 중원·기존 스트라이커 유지. 중앙 중원에서 한 명이 전진해 투톱 형성. |

- [Chicago Fire FC의 Michael Cox 인터뷰](https://www.chicagofirefc.com/news/what-4-1-4-1-qa-zonal-markings-michael-cox-between-lines)는 `4-1-4-1`이 `4-3-3`, `4-4-2`, `4-5-1`, `4-2-3-1`과 연결되는 맥락을 다룬다. 특히 단일 피벗과 더블 피벗의 역할 차이는 별개라고 설명하므로, 같은 포메이션으로 뭉뚱그리지 않고 역할 변경 비용을 적용한다.
- `4-4-2 ↔ 4-4-1-1`, `3-5-2 ↔ 3-5-1-1`, `3-4-1-2 ↔ 3-4-2-1`, `4-5-1 ↔ 4-4-1-1`의 개별 선수 대응은 전술 명칭의 동등성 주장이 아니라, 나머지 라인을 보존하는 앱의 구조적 해석이다.

## 목록에 없는 모든 변경

다른 묶음 사이의 변경, `3-4-1-2`, `3-5-1-1`, `3-3-1-3`도 처리한다. 골키퍼는 고정하고, 현재 역할과 가까운 역할, 같은 좌우 측면, 짧은 이동 거리를 선호하는 비용으로 **11개 슬롯 전체의 합이 최소인 일대일 배치**를 찾는다. 앞에서부터 가까운 빈자리에 채우는 방식이 아니므로, 먼저 처리한 선수가 다른 선수의 적합한 자리를 차지하는 문제를 피한다.

동률은 일정한 슬롯 순서로 결정한다. 선수 이름이나 API의 넓은 `D/M/F` 분류보다 현재 슬롯을 우선하므로 사용자가 의도적으로 옮긴 선수도 그 자리의 역할을 이어받는다. 현재 지원하는 23개 포메이션의 모든 529개 조합에서 직접 왕복 전환이 정확히 복원되는 것을 검증했다. 서로 다른 여러 묶음을 거친 전환은 매번 현재 배치를 최적화하며, 과거 API 배치로 강제 복원하지 않는다.
